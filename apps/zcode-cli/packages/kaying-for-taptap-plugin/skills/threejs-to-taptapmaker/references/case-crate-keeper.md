# 参考案例：Crate Keeper（three.js 3D 推箱子 → Maker）

这是本插件全部结论的来源案例。规模：原版 34 个 JS 文件 / 约 240KB；转写产出 13 个 Lua 模块 + 1 入口，约 5300 行，另加 8 个音效与 1 首 BGM。

## 原版结构（转写映射）

| 原版模块                                                    | 职责                                 | 转写目标                              |
| ----------------------------------------------------------- | ------------------------------------ | ------------------------------------- |
| `levels/data.js`、`worlds.js`、`daily-data.js`              | 120 关 + 8 世界主题 + 48 每日池      | `CKData.lua`（`t3m levels` 直接转换） |
| `rules.js`、`solver.js`、`levels/rows.js`                   | 移动/机关规则、最少推 BFS、旋转镜像  | `CKRules.lua`                         |
| `game.js`、`save.js`、`end.js`、`daily.js`                  | 流程、星级金币、存档、结算、每日轮换 | `CKGame.lua`                          |
| `scene/stage.js`、`board.js`、`board-mech.js`               | 取景/光照、棋盘、五种机关            | `CKBoard.lua`                         |
| `scene/keeper.js`、`crate-tex.js`、`actors.js`              | 角色、箱面、动画队列                 | `CKActors.lua`                        |
| `scene/geo.js`、`tex.js`                                    | 圆角盒与 Canvas 纹理                 | `CKGeo.lua`、`CKTex.lua`              |
| `scene/props.js`、`decor.js`、`fx.js`                       | 道具、背景、粒子                     | `CKProps.lua`、`CKDecor.lua`          |
| `ui/hud.js`、`screens.js`、`panels.js`、`shop.js`、`i18n/*` | 全部界面与中英词典                   | `CKUI.lua`、`CKI18n.lua`              |
| `audio.js`                                                  | WebAudio 合成音效                    | 生成的音频文件 + `CKAudio.lua`        |
| `main.js`、`input.js`                                       | 主循环、输入                         | `main.lua`                            |

## 关键数字（用于交叉验证）

| 项              | 值                                                                 |
| --------------- | ------------------------------------------------------------------ |
| 关卡数 / 每日池 | 120 / 48（转换后条目数必须一致）                                   |
| 第 1 关         | `w=7,h=3`，1 箱 1 目标，`par=3`，`pushes=2`（求解器实解 = 2 推 ✓） |
| 相机            | FOV 32，倾角 0.95 rad（横屏），玩法留白 top1.2/bottom1.0/side1.4   |
| 光照            | 太阳 2.3 + 环境 0.44（换算后水平面 ≈ 1.05）                        |
| 逐实例染色      | 地板 0.97 / 墙 0.96 / **盖板 1.32**                                |
| 镜面            | `MatSpecColor = 0.04`                                              |
| 动画            | 步伐 0.13s / 滑行每格 0.075s / 转身 18 rad·s⁻¹ 系数                |
| 亮度验收        | 棋盘区域中位亮度：修前 38 → 修后 93（原版 108，差距 14%）          |

## 本次踩到的坑（按发现顺序）

1. 取景模式接线错误：把游戏模式字符串当取景模式传 → 关卡用了菜单取景（dist 16.3 vs 9.6，横移 3.78 格）
2. 坐标手系镜像：画面左右颠倒 + 左右键反
3. 几何 UV 不同源：箱面箭头被旋转 90°
4. 环境光 no-op：`ambientColor` 无效 → 画面暗 2.5 倍
5. 镜面 F0 用错量级：掠射角泛白
6. 逐实例染色丢失：盖板偏暗
7. Canvas 纹理用几何体近似（走偏成"风格化"）→ 改为按绘制逻辑转写
8. 接触阴影平面：引擎 alpha 混合不兼容 → 渲染成亮面板
9. UI 换屏在事件派发中执行 → 点击后死循环（294s CPU / 135s 挂钟）
10. 标题屏缺确认键 → 键盘无反应
11. "无响应"实为窗口未获焦点（日志里没有任何输入事件）
12. `preview refresh` 收尾误杀新会话 → 改"停 → 等 → 起"

每条的症状/证据/修法见 [pitfalls.md](pitfalls.md)。

## 复用的诊断手法

| 手段                                     | 用途                             |
| ---------------------------------------- | -------------------------------- |
| 截图像素统计（均值/中位亮度/色相比）     | 判断亮度与色偏，不靠肉眼         |
| 导出纹理为 PNG（`Image:SavePNG`）        | 确认贴图内容对不对               |
| 打印材质参数与 `GetTexture(TU_DIFFUSE)`  | 确认材质与绑定                   |
| 自驱 + 埋点（临时让 `Start()` 直接进关） | 不依赖用户点击就能复现调用链     |
| `Get-Process` 的 `Responding` + CPU 时间 | 区分"真死循环"与"只是没输入"     |
| `GetForegroundWindow` 比对窗口句柄       | 判断输入为何没到达               |
| 输入事件日志（收到鼠标/按键就打一行）    | 区分"没收到输入"和"收到了没处理" |
