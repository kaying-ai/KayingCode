调用独立 MCP `blender_doctor` 的 `blender_doctor` 工具。该工具无需 Blender MCP 主服务可用。

先给当前阻塞项、证据和 `nextAction` 给出的下一步。需要安装时优先建议 `/blender-install`，并给出 `installation.addonPath` 的完整可复制路径、期望版本与协议，以及只读发现的 `blenderVersion`、`addonsDir`；说明 `executionHost` 是文件所在主机、`target` 是 Blender 握手地址。向用户区分磁盘发现的副本与 `addon.running` 实际报告的版本。握手超时时说明仍需复查。诊断期间只读，不安装软件、不修改用户配置、不清缓存、不执行 Blender Python。

## 生成结果与验收排查

用户报告相似度、预览、质量或耗时问题时，从当前任务的工具记录、产物目录和用户的参考图开始。实时连接未就绪时仍可检查现有证据。需要回看另一个会话时，仅查询与该任务匹配的记录。缺少证据时把对应项标为未验证。

1. **配对和能力**。记录本轮实际的 Skill 路径、MCP 快照、运行实例的 add-on 和协议。用已记录或可用的 `get_addon_status` 核对当时或当前的素材库、生成服务和 Premium 可用性，标明证据时间。工具列表出现 `generate_3d` 只表示已注册。连接拒绝、配对不符、服务关闭和权限各自给出结论。
2. **参考和路线**。核对主参考来源、实际读图结果和模型是否收到图像。可用时从本轮模型请求的图片块验证，避免把路径文本当作图片。顺着已调用的工具和用户授权判断实际走了已有资产、参考图生成还是手写 `bpy`。记录 `/blender-from-reference`、Skill 和参考图指南的实际使用情况，检查是否通过配对的 MCP 修改场景，以及路线降级的时间和说明。
3. **产物和验收**。一起查看原图、草模、同向终稿预览及现有脚本。按轮廓/比例、脸和发型、姿势、服装结构、色彩和材质列出最影响结果的差距。用已有的场景检查和导出数据核对对象、网格、贴图、骨骼或动画，仅要求与交付类型相关的字段。区分造型、材质与灯光。成片只能证明曾经出图，带渲染的 `.blend` 还要找保存和复读后的活动相机、贴图证据。指出是否在交付前有实际对照、是否运行了资产检查，以及差距是否仍被标成通过。
4. **耗时和错误**。按记录对齐开始、首个可用参考、草模自检、开始细化及交付时间。识别细化前缺少剪影核验、常规阶段等待用户确认、长时间素材检索、重复 `Read` 预览、反复整场景重建，以及工具返回文本错误却显示完成。有暂停时，记录原因、能否自行恢复和等待时长。

按「已确认原因 / 未验证项 / 优先修复」收口，引用相关文件或回合。只摘录诊断所需的事实，省略请求头、凭据和无关会话。诊断使用已有产物和只读接口，保留现有 Blender 场景和文件。

工具不可用时，通过 shell 运行：

```sh
node "${KAYINGCODE_PLUGIN_ROOT}/scripts/doctor.mjs"
```

若用户继续要求修复，依照 Blender skill 执行对应步骤，再次运行 doctor 验证；不要运行上游 setup 或修改其他 MCP 客户端配置。
