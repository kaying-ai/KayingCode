# 我的 TapMaker 游戏卡片

- 列表按内容区宽度排列。达到 54rem 显示三列，达到 36rem 显示两列，其余宽度单列铺满。网格居中，最大外宽 64rem，双列和三列布局额外保留两侧各 2rem 留白。卡片间距与内边距为 16px。
- 游戏名和置顶标记放在标题区，下一行左侧为类型及阶段、本地/云端状态标识，右侧为最近活动日期。项目 ID 仅供内部识别项目及恢复操作使用。底部用分隔线区分本地路径或云端状态与对应操作，操作按钮右对齐。
- 长游戏名和路径可截断，保留完整 `title`。日期和操作按钮不受长文本挤压。缺少类型、阶段或日期的项目继续正常展示。
- `TapMakerProjectsPage` 负责布局，`useTapMakerProjects` 继续提供列表和操作状态。打开、恢复、刷新与授权沿用原有回调、平台限制和失败提示。

## 状态区分

- 卡片用边框样式区分本地状态，不新增装饰色块：已加载到本地使用实线 `border-card-border`，仅云端使用虚线 `border-border`；两种状态都保持 `bg-card`。
- 状态表达分两层：
  - 本地状态用卡片右上角顺时针 45°（从顶边斜向右边缘）的横幅表达：文字“本地”，`bg-success/15` 底色 + `text-success`，由卡片 `overflow-hidden` 与圆角裁切；横幅只作状态提示，不拦截点击。标题区在本地状态下预留右侧空间，置顶 Pin 不得被横幅遮挡。
  - 云端状态保留在标题下方元数据行：`text-foreground-subtlest` 空心点 + “云端”；状态只由 `localDirectory` 决定。
  - 底部操作区按状态分别表达：本地卡片不展示路径，改为「打开所在文件夹」和「在 Agent 中打开」两个按钮；云端卡片保留“尚未加载到本地”与「恢复到本地」。
- 「打开所在文件夹」调用系统文件管理器（`platform.openInFileManager`），桌面端可用，非桌面壳层禁用；失败时 toast 复用 `appHeader.openInFileManagerFailed`。「在 Agent 中打开」沿用先登记项目、再带项目 ID 打开工作区与草稿的既有链路。
- 置顶状态只保留标题区 Pin 图标，不改变卡片边框或状态点；置顶不是本地状态。
- 卡片游戏图标底板：本地使用 `text-foreground`，云端保持 `text-foreground-subtle`，两者底板均为 `bg-surface`。
- 恢复中的项目沿用操作按钮内的 Loader 与禁用态，不新增第二套加载样式。
- 状态点、边框和图标全部使用现有语义/表面 token，浅色、深色和手机布局保持同一规则；不使用 success 填充整卡或图标底板。

## 验收

- 1536px 桌面视口（含 256px 侧栏）三列，1080px 桌面视口两列，390px 手机视口单列。同排操作区对齐，卡片正文与悬停文字均不显示项目 ID，日期仍可见。
- 1536px 视口中三列卡片等宽，单张卡片宽度不超过 320px，网格两侧留白对称。手机沿用页面边距。
- 中文长游戏名、英文操作按钮及长本地路径同时存在时，页面无横向溢出，完整值可查看，按钮保留完整文本与原有操作能力。
- 本地与云端卡片混排时，无需阅读按钮即可通过边框、状态点和图标颜色区分；本地卡片两个操作按钮在单列、双列、三列和手机布局下均完整可点，不出现省略或横向溢出。
- 「打开所在文件夹」打开 `localDirectory`；「在 Agent 中打开」进入对应项目草稿，二者互不替换。置顶、恢复中状态不改变该判定。
