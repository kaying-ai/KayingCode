## 报告遗漏的许可问题

1. SPDX AND/OR 以去括号字符串拆分，会把 `GPL-3.0-only AND (MIT OR BSD-3-Clause)` 错判为 green。本次新增直接开发依赖 spdx-expression-parse，按 AST 判断，测试证明限制不会被 OR 旁支抹掉。
2. `NPM_CONFIG_LOCKFILE_ONLY` 的环境残留会使“锁图/安装图”两次查询都读同一图；新增强制 true/false 环境及安装快照文本一致性（仅 CRLF 归一化），仍保留实际生产图比较。
3. 固定上游 Web 自带旧声明，当前 dist 中声明哈希与本仓生成文件不同。构建后同时保留上游原文与当前产品声明，manifest 记录哈希，CF 真集成核对两份公开文件和 rel=license 链接。不能只确认文件存在。
4. 之前静态材料已补齐 18 个包来源、5 份 pnpm 补丁和 native 路径搬迁登记；本次不回退这些修复。新增复核记录必须纳入生成输入哈希。
5. 现有 23 项 reviewRequired 涵盖 publisher 原文缺口、复制技能、Skia/QuickJS/WASI 构建来源、Rust 标准库来源；这不是纯标识误报。当前精确 npm gitHead 原文候选核查多处返回 404/无公开仓库，不能拿当前 main 许可替代旧版本，更不能删除缺口来“通过 strict”。
6. mdn-data@1.1.4 与 webpack-chain@6.5.1 的 MPL 原文与精确源码地址可以登记；本机核对两份 npm 源码归档均匹配锁文件的 SHA-512。当前前者只在开发链，后者在完整生产图。后者的最终发行制品、改动及对应源码交付尚未验收，strict 材料保留 artifact-source 事项；基本检查通过不代表发行许可完成。
