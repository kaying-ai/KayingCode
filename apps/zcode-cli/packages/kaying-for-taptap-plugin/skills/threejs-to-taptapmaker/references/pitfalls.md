# 坑位清单（症状 → 根因 → 证据 → 修法）

全部来自一次完整的实机转写（three.js 3D 推箱子 → Maker）。每条都写清"当时看到什么、怎么定位的、怎么修的"，因为**定位方法比结论更可复用**。

> **预览 `Token expired, please rebuild to refresh.` 不在本清单。**  
> 请先读插件根目录 [`README.md`](../../../README.md)：那是 CLI PAT 与 webview OAuth 两套 token 的问题，反复 rebuild 无效；正确路径是清预览缓存 → 面板内登录 → 再 build。

## A. 画面/渲染

### A1 画面整体暗 2.5 倍，颜色发灰

- **症状**：色相对（暖棕还是暖棕），但棋盘区域中位亮度只有原版的 1/2.5。
- **根因**：`zone.ambientColor` 在默认 `AMBIENT_PREBAKED`/`AMBIENT_SKYBOX` 模式下是 **no-op**（引擎硬下发 `cAmbientColor=(0,0,0,0)`），环境光完全没参与照明，只剩太阳。
- **证据**：①引擎文档 `engine-docs/recipes/rendering.md` 明确写了这一点；②截图像素统计（棋盘区域中位亮度 38 vs 原版 108）；③材质诊断打印显示材质取值正确、贴图已绑定 → 排除材质问题。
- **修法**：`zone.ambientSource = AMBIENT_COLOR` + `zone.ambientColor = Color(...)`。修好后**原版的光照强度就能直接沿用**（本引擎 PBR 漫反射项除以 π：`0.44 + 2.3×0.83/π ≈ 1.05`）。

### A2 掠射角的地面/台板整片泛白，正对镜头的地方正常

- **症状**：远处地面、斜视角的台板像蒙了一层白；离相机近、正对的面颜色正常。
- **根因**：three.js `MeshStandardMaterial` 非金属的镜面 F0 默认 **0.04**（从不显式设置）；本引擎要显式给 `MatSpecColor`，我写了 0.45（高 10 倍），掠射角下 Fresnel 把高光推到接近全反射。
- **证据**：采样发现"R 通道对得上、G/B 被抬高"——这是叠加白色高光的特征；且理论期望值 `(222,199,163)` 与实测 `(209,195,162)` 在修掉高光后吻合。
- **修法**：所有材质的 `MatSpecColor` 统一为 `Color(0.04, 0.04, 0.04, 1.0)`。

### A3 箱子上的箭头是横向的（应该朝上），方盒没有圆角

- **症状**：贴图能显示，但方向被旋转 90°；形状比原版"硬"。
- **根因**：内置 `Models/Box.mdl` 的 UV 布局与 three.js `BoxGeometry` 不同；原版用的是 `roundBox()`（圆角盒，UV 来自 BoxGeometry）。
- **证据**：原版 `scene/geo.js` 的 `roundBox()` 实现是"细分盒投影到圆角外壳"，其 UV 沿用 BoxGeometry。
- **修法**：改用与本引擎 three.js 兼容的程序化几何 `RoundedBoxGeometry(w, h, d, seg, r):ToModel()`，参数与原版调用一一对应（`roundBox(0.8,0.78,0.8,0.09,3)` → `RoundedBoxGeometry(0.8,0.78,0.8,3,0.09)`）。

### A4 一整块均匀的浅色面板盖住地面

- **症状**：棋盘周围出现一块比台座大一圈、颜色不随光照变化的浅色矩形。
- **排查过程（值得复用的排除法）**：
  1. 采样该区域的像素，**三次改光照后数值完全不变** `(218,211,200)` → 说明它不是被照明的 3D 表面。
  2. 导出纹理像素（`Image:SavePNG`）→ 纹理内容正确（混凝土地面 `(0.812,0.682,0.525)` = 原色 `#cfae86`）。
  3. 打印材质绑定 → `tex=true size=128x128 tech=true` → 绑定正常。
  4. 比对边界 → 尺寸正好等于原版"接触阴影平面"（`PlaneGeometry(w+5, h+5)`）。
- **根因**：照抄原版的半透明接触阴影平面（`MeshBasicMaterial({transparent, opacity:0.28})`），但本引擎的 alpha 技术不按 three.js 的方式混合，把它渲染成了一块亮面板。
- **修法**：删除该平面，接触暗部交给太阳的真实阴影；在代码里写明这是引擎能力差异。

### A5 纹理平铺丢失（地面没有细缝纹）

- **症状**：地面颜色对，但一片纯色，没有原版的细分格缝。
- **根因**：原版对地面纹理设了 `repeat.set(30, 30)`（120 单位圆盘上 4 单位一格）；本引擎纹理 UV 固定 0..1，没有 UV 缩放接口。
- **修法**：**认了**这是能力边界（颜色正确即可），或在纹理内部画更多份图案（受纹理分辨率限制）。写进验收说明，不要继续瞎调。

## B. 逻辑/输入

### B1 画面左右镜像，且左右方向键是反的

- **症状**：原版第 1 关"玩家在左、目标在右"，转写后正好颠倒；按右往左走。
- **根因**：three.js 右手系，本引擎左手系（同 Unity）。相机在 +Z 看原点时，世界 +X 落在屏幕**左**侧。
- **证据**：关卡数据里 `p=8`（x=1，左）、目标在 x=5（右），而截图里目标在左 → 确认镜像。
- **修法**：新增统一映射 `CellWorldX = (w-1)/2 - x`，**棋盘、角色、装饰道具、拾取、提示箭头全走同一函数**。

### B2 朝向反了：按右走，人朝左（"背着身子走"）

- **症状**：移动方向正确，但角色模型朝向与行进方向相反。
- **根因**：修 B1 时只改了位置映射，**漏了朝向表**。原版 `DIR_YAW = {180, 90, 0, -90}` 里"右"= 世界 +X；镜像后"游戏里的右"= 世界 −X，左右两项要互换。
- **修法**：`DIR_YAW = {180, -90, 0, 90}`。**教训**：任何"格子 → 世界"的映射（位置、朝向、射线命中、箭头偏移）都要在同一处收口。

### B3 点"开始/下一关"后界面卡死，Windows 报"无响应"

- **症状**：窗口可见但点任何东西都没反应；进程 `Responding: False`，**135 秒挂钟消耗 294 秒 CPU**（真死循环）。
- **定位方法（关键）**：
  1. 看日志：帧率输出在点击那一刻停住 → 卡在点击处理链里。
  2. 用**自驱 + 埋点**复现，不依赖用户点击：临时让 `Start()` 直接调用进关、以及连续切屏（title→play→title→map→shop→title），结果**全部通过**。
  3. 于是锁定唯一差别：**点击时是在 UI 事件派发中途**执行换屏。
- **根因**：在 UI 按钮回调里替换/销毁整棵控件树，库随后还会访问已释放控件的 hover/pressed 状态 → 原生层自旋。
- **修法**：换屏动作一律延迟到下一帧（`Defer(fn)`，在 `Update` 里执行）。**所有**入口都要覆盖：开始、关卡地图、工坊、设置、每日、HUD 按钮、过关弹窗的下一关/再玩/地图、暂停弹窗的关卡地图/设置、设置返回、每日开始。

### B4 标题屏键盘完全没反应（看起来像卡死）

- **根因**：转写遗漏。原版 `input.js` 在非玩法界面绑了 `Enter/Space` 确认，我只绑了玩法内按键。
- **修法**：标题屏 `Enter/Space` 开始、`Esc` 返回。

### B5 "无响应"其实是窗口没拿到焦点

- **症状**：用户报"无响应"，但日志里**一条输入事件都没有**。
- **定位方法**：`Get-Process` 看 `Responding`；用 `GetForegroundWindow` 比对游戏窗口句柄 → 前台是别的应用（编辑器），游戏在后台。
- **修法**：`AppActivate` + `SetForegroundWindow` 把游戏窗口切前台；并在输入处理里加"[IN] 收到鼠标/按键"日志，这样"没收到输入"和"收到了但没处理"一眼可分。

### B6 启动后立即 failed（进程被误杀）

- **症状**：`preview start` 报 running，几秒后 status 变 failed，日志停在首帧着色器编译。
- **根因**：`preview refresh` 的收尾进程与新会话竞争，把刚起来的 Runtime 杀掉了。
- **修法**：改用"`stop` → 等几秒确认无残留进程 → `start`"的顺序，而不是 `refresh` + `start`。

## C. 环境/工具

### C1 生成 1 秒音效得到静音文件

- **症状**：音频文件字节数完全相同、`ffprobe` 有 1.03s 时长，但音频帧全空。
- **证据**：`xxd` 看文件头（ID3 + Xing 帧表）与同类文件对比；第二批生成的文件带有效帧表。
- **修法**：生成后**必须校验非静音**（文件头/时长/批量对比），静音文件删掉重生成；同名重复时保留有效的那份并统一命名。

### C2 抓源码时 curl 报证书吊销检查失败

- **症状**：`curl: (35) schannel: CRYPT_E_REVOCATION_OFFLINE`。
- **修法**：加 `--ssl-no-revoke`（保持验证、容忍吊销服务器不可达）；`t3m fetch` 已内置该回退。

### C3 输出"看起来对但跑不起来"的 Lua

- **例子**：`--name CKData.LEVELS` 生成 `local CKData.LEVELS = {`（非法）。
- **修法**：带点号的名字按字段赋值生成（`CKData.LEVELS = {...}`）。**任何代码生成器都要把产物丢给引擎编译一遍**，别只看文本像不像。

## D. 程序化几何与角色（frog-crossing 转写实测）

这一组是**最贵**的坑：失败形态统一是"数据全对、画面全无、日志干净"。唯一有效的定位手段是
把画面画出来看（见 [runtime-loop.md](runtime-loop.md) 第 5、6 节）。

### D1 合并出来的网格画成一堆碎片/棍子

- **症状**：地面格线之类的部分面碰巧成立，其余全变成乱三角与细棍。
- **根因**：`CustomGeometry` **没有索引缓冲**，它按 `DefineVertex` 的**顺序**每 3 个顶点组一个三角形。
  把合并几何的*顶点表*按序上传、丢掉索引表，引擎就会拿任意三个连续顶点当三角形。
  此前 headless 自检校验的是合并后的*数据*（顶点数、绕序、包围盒）——数据一直是对的，
  错的是上传方式，所以自检全绿也照样花屏。
- **修法**：按 `merged.idx` 逐三角形发 3 个顶点（顶点数 = 3 × 三角形数）。
  连带约束：仍受 **16 位索引上限（~65k 顶点 ≈ 21k 三角形）**约束，超限**不报错**，只是索引回绕、面消失
  → 大网格按块切成多个网格节点（实测地面按 ~18k 三角形一块切）。
- **定位手法**：截图放大看；或给该网格换纯色材质，先确认是"形状"问题而不是"颜色"问题。

### D2 `FillModel()` 之后不设包围盒 → 网格被视锥剔除，静默不画

- **症状**：运行时生成的网格完全不出现；日志干净；`StaticModel.inView = true`、
  `GetNumVertices` 正常、材质已挂、变换正常——全都指向"应该在画"，但屏幕上什么都没有。
- **根因**：`FillModel()` 留下的包围盒不覆盖几何，渲染器按包围盒做视锥剔除 → 直接判定不可见。
- **修法**：显式 `model:SetBoundingBox(BoundingBox(Vector3(min), Vector3(max)))`，并**留余量**
  （0.1~0.2）：风摆/顶点位移的 shader 会把顶点推出原包围盒，余量不够会再次被剔除。
- **定位手法**：换平色材质排除材质因素，再打印包围盒与几何范围对比。

### D3 在目标节点（或其子树）上建 Model → 那个节点的 StaticModel 永远不画

- **症状**：同一套几何挂在场景根下能画，挂在角色子树下不画；`SetParent` 到新节点也没用。
- **根因**：为了 `FillModel` 而在**将要持有该 StaticModel 的节点**（或其后代）上临时创建一个
  `CustomGeometry`，会让该节点上的 StaticModel 此后不再被绘制（inView、几何、材质全部正常）。
- **修法**：`Model` 一律在一个**子树之外的 scratch 节点**上构建（建完 `Remove()` 掉临时子节点）；
  角色这种"每帧动、数量少"的小网格干脆走 `CustomGeometry` 直挂路径（引擎 procedural-geometry 手册的路径 B），
  不要复制成共享 Model。
- **定位手法**：把同一个模型分别挂到场景根与角色根，看差异落在哪棵子树。

### D4 关节角色与静态道具要走两条不同的出图路径

- **结论**：静态道具（每格一个、数量大）→ 合并几何 + 共享 `Model` + `StaticModel`（靠引擎合批）；
  关节角色（部件少、每个部件独立旋转/换色）→ 每个部件一个节点 + `CustomGeometry` 直挂。
- **理由**：前者省内存，后者绕开 D3；两条路都验证过能画。
- **附带**：逐实例染色在两条路径上的入口不同（`StaticModel.instanceColor` / `CustomGeometry.instanceColor`），
  surface shader 里都从 `INSTANCE_COLOR` 取，但这个内建量**只在顶点阶段可用**（见 E5）。

## E. 引擎 API 语义（静态检查一律看不见）

以下每条都是"LSP 0 error、lint 全绿、远端构建成功"状态下真实崩掉的原因。`t3m lint` 已覆盖可机械判定的部分。

### E1 引擎全局被局部变量遮蔽

- **症状**：启动第一步就崩：`attempt to call a nil value (method 'GetResource')`；该文件所有 `cache:…` 调用失效。
- **根因**：`local cache = {}`（用来缓存 shader 声明）遮蔽了引擎注入的全局 `cache`（ResourceCache）。
- **修法**：引擎全局一共这些：`audio cache console context engine fileSystem graphics input localization log network renderer time ui`
  —— 任何同名局部变量都会遮蔽它。局部缓存一律改名（`cache` → `shaderCache`、`ui` → `ui_`）。
  `t3m lint` 规则 `engine-global-shadow`：模块级 + 该文件后面还在 `name:…` 调用 → 高风险。

### E2 `Vector2 / Vector3` 是值类型：出参写回无效

- **症状**：`cameraFor(tx, tz, out)` 之后相机纹丝不动（永远在原点，看进地形内部）。
- **根因**：引擎文档写明"函数传参会复制值"；写出参 API 在 Lua 侧完全不生效。
- **修法**：返回多个标量（`return x, y, z`），或返回一张表；不要写出参。
- **附带**：`node.position` 这类属性**读取**回来也是副本，要改就整体赋值（`node.position = Vector3(...)`）。

### E3 `Quaternion:EulerAngles()` 返回的是一个 `Vector3`

- **症状**：`local rx, ry, rz = q:EulerAngles()` 之后 `rx` 是向量、`ry/rz` 是 nil，随后逐帧
  `attempt to perform arithmetic on a nil value (local 'rz')`。
- **修法**：读返回值的 `.x/.y/.z`；更省事的做法是**自己用标量记录姿态**，别从四元数反读。
- **附带**：引擎欧拉顺序是 **Ry·Rx·Rz**，单位是**度**。

### E4 没有 `renderer:Render()`

- **症状**：`attempt to call a nil value (method 'Render')`。
- **修法**：删掉。设置好 `renderer:SetViewport(0, Viewport:new(scene, camera))` 后，引擎每帧自己渲染。

### E5 shader 阶段内建量：`INSTANCE_COLOR` 只在 `vertex()`

- **症状**：`Unknown identifier in expression: 'INSTANCE_COLOR'`，且这个失败会**级联**成整屏不渲染
  （一个 shader 编译失败打断了 `Start()` 的后续步骤）。
- **修法**：在 `vertex()` 里 `v_inst = INSTANCE_COLOR;` 用 varying 带进 `fragment()`。
  材质创建**必须能回落**（失败时给一个显眼的红色 PBR 材质继续跑），否则单点失败会拖垮整个启动。
- **自查**：`t3m lint` 会扫 `assets/**/*.shader` 的 `instance-color-in-fragment` 规则。

### E6 UI 根面板默认不透明：整个 3D 画面被糊住

- **症状**："点击开始后场景是空的"——其实场景在，只是被一块不透明的 UI 面板盖住。
- **根因**：原版 CSS 里 `#ui`、`.screen` 都没有背景色（3D 画面就是底），转写时给根面板填了 `#fffaf0`。
- **修法**：根面板/容器面板一律**显式透明**，只给确实需要底色的子面板上色。
- **定位手法**：截图像素采样——该区域颜色**不随光照变化**，就说明它不是被照明的 3D 表面。

### E7 UI 方法表与元表要对上

- **症状**：所有 `ui:xxx()` 都是 `attempt to call a nil value (method 'xxx')`。
- **根因**：方法定义在模块表 `M` 上，实例的元表却指向了另一个表。
- **修法**：`setmetatable({}, {__index = M})` 里的 `M` 必须是真正持有方法的表。

### E8 未随包发布的资源不要请求

- **症状**：日志里刷 `ERROR: Could not find resource audio/fc_bgm.mp3`。
- **根因**：代码无条件请求了两个从未生成的音乐文件；`ResourceCache:GetResource()` 对缺失路径会记 ERROR。
- **修法**：只请求确实随包发布的文件；可选资源登记在表里，文件不在就不请求。
- **反面教训**：不要用 `cache:Exists(path)` 做存在性探测——它只看磁盘文件，对本引擎的 manifest 资源
  一律返回 false，会把全部音效静默静音（实测踩过并回滚）。**这个引擎没有给 Lua 的 manifest 探测接口。**
- **自查**：`t3m lint` 的 `resource-not-shipped` 规则会核对 `GetResource(...)` 的字面量路径与 `assets/` 实际文件。

### E9 `LightGroup/Daytime.xml` 自带一盏太阳

- **症状**：画面整体偏亮（两盏平行光叠加），日志报缺 `Cube/Day/…dds` 的 IBL 立方图。
- **修法**：不要加载它。太阳自己建（`Light` + `LIGHT_DIRECTIONAL` + `brightness`），
  环境光用 `zone.ambientSource = AMBIENT_COLOR` + `zone.ambientColor`。
- **附带**：要区分"引擎级"与"项目级"报错——`Cube/Day/DaySpecularHDR.dds`、`themis_x64.dll`
  在任何工程都会报，不是你的问题（`t3m rlog` 会自动分到 noise 一类）。

### E10 环境光/间接光要按 1/π 折算

- **症状**：照搬原版强度后整体亮约 3 倍（或反过来暗 2.5 倍）。
- **根因**：three.js 的间接光会乘 `BRDF_Lambert(1/π)`，本引擎的 `cAmbientColor` 是直接相加。
- **修法**：环境光按 1/π 折算再传；环境光与太阳**一起标定**（只改一个永远对不上），
  判定用截图像素统计（中位亮度差 <15%），不靠肉眼。

## F. UI 文本与布局（第三次转写：Tower Guard 实测）

这一组的统一形态是"**界面能跑、日志干净、两道门禁全绿，字还是被画坏了**"——`t3m lint` 0 高风险、
`t3m rlog` PASS、远端构建成功都拦不住，因为它们是**绘制期**的问题，不是错误。
判据也只有一条：**把文字宽度量出来**，别用肉眼和感觉定尺寸。

### F1 按钮上的字被裁到半个字（中文字形左右各切一半）

- **症状**：底部建造栏的塔按钮显示成 `弓箭手 7(`——首字左半边、末尾数字右半边同时被切，
  看起来像字形损坏或字体加载失败。
- **根因**：`urhox-libs/UI` 的 **Button 用单行 `nvgText` 绘制自己的 text**：没有换行、没有省略号、
  没有 `numberOfLines`，超出边框的部分被按**边框盒**裁剪（不是缩成省略号，而是从字形中间切断）。
  转写时把"名称 + 费用"写成一个字符串（`I18n.t("tw_"..key) .. "\n" .. cost`）并按 96px 定宽：
  `\n` 不是换行符（单行绘制把它当普通字符画在同一行），整串约 190px 挤进 96px 的框，
  居中绘制后左右各溢出一截 → 两边都被切。
- **证据**：库源码 `urhox-libs/UI/Widgets/Button.lua` 渲染段是 `nvgText(...)` +
  `nvgIntersectScissor(nvg, l.x, l.y, l.w, l.h)`；文本宽度只在构造 / `SetText` 时按**单行**
  （`UI.MeasureTextWidth`）量一次，用于算固有宽度——一旦给了显式 `width` 就按显式值走，不会再校验。
- **修法**：两行内容（名称 + 费用）改成 **Panel + 两个 Label**（Label 支持 `\n` 与
  `whiteSpace = "normal"` 换行，也会按宽换行）；必须单行的按钮，宽度用
  `UI.MeasureTextWidth(text, Theme.FontSize(字号pt), 字体, 字距)` 量出来，再加左右 padding
  （主题默认 `paddingHorizontal = 16`，两侧共 32），不要凭感觉定宽。
  `t3m lint` 规则：`ui-button-newline`（高风险）、`ui-text-width-hardcoded`（中风险）。

### F2 文字不会自动缩小：`defaultAutoFitText` 只在引擎 i18n 启用时为真

- **症状**：英文界面看着正常（"Cannon" 塞得进 96px），切成中文（"寒霜水晶"）就溢出；计费数字涨到 4 位同样。
- **根因**：库里确实有 shrink-to-fit 路径（`UI.MeasureTextFit`），但只在 `UI.defaultAutoFitText == true` 时启用，
  而这个开关由 `UI.Init` 的 i18n 决定（`UI.defaultAutoFitText = i18n and i18n.IsActive()`）。
  **项目自带 Lua 词表（自己的 `I18n.t`）时引擎 i18n 模块没启用，这条路径是关的**——一个字都不会缩。
  另外 CJK 字形约 **1em** 宽（`15pt` ≈ 20px），拉丁字母约 0.5em：照英文定宽再换中文必然溢出。
- **修法**：按**最长语言**量宽度；需要更稳就给控件显式打开 `UI.defaultAutoFitText = true` 并设
  `minFontSize`（库下限 8pt，建议 11 以上）作为兜底。两者都做最省事：量出来的宽度 + autofit 兜底。

### F3 关掉库自带的布局溢出检查 = 关掉唯一的机械布局体检

- **症状**：`UI.SetOverflowWarnings(false)` 之后日志安静了，但选择面板（320px）里塞着 344px 的子控件、
  底栏（116px）里塞着 118px——压边、错位，换个分辨率或长字符串才暴露。
- **根因**：库在每次 `UI.Layout()` 之后跑 `CheckOverflow`，报的是**子控件尺寸超出容器**的真实数字
  （`children=344x…, container=…x320`）。它抛错（`string.format "%d"` 撞上非有限值）说明某个控件的
  box 是 **NaN/inf**——那是真 bug 的信号（按未设置的尺寸、0 缩放算出的 `left/top`，或 100% 尺寸的父面板，
  再被 `math.floor` 原样留成 nan），把检查关掉等于把体温计砸了。
- **修法**：定位那个尺寸非有限的控件并修掉，保持检查开启；确认是库自身在嵌套面板上误报再考虑关。
  `t3m lint` 有 `ui-overflow-check-off` 规则提醒。

### F4 局部函数与控件方法同名 → 自递归，界面数字静默冻结

- **症状**：金币、波次、得分、倒计时永远停在初始值；**没有报错、没有 nil，lint / rlog / 远端构建全绿**，
  只有盯画面才知道不对。
- **根因**：`local function setText(widget, text) … setText(widget, text) … end`——函数体里的 `setText`
  就是这个局部函数本身（不是控件方法），那一行是**递归调用自己**；上面又有"值没变就跳过"的守卫，
  第二次进入立刻返回，于是**什么都不做**：`widget:SetText` 从未被调用。
- **证据**：用 Lua 5.4 跑同一形状的最小复现——调用后控件值仍是初始值、方法调用次数 0、
  守卫字段被正常写上（即"看起来走了流程，其实没写"）。
- **修法**：写成 `widget:SetText(text)`。**任何与控件方法同名的 local 包装都有这个坑**
  （`SetVisible` / `SetStyle` / `SetSize`…）；要防抖就保留"比较上次值"的守卫，但真正写值的那一步必须是方法调用。
  `t3m lint` 规则：`self-call-shadows-method`（高风险）。

### F5 每个界面 × 每个状态都要看一遍

文字溢出不是"某个按钮写错了"，而是**每个动态字符串的控件都欠一次测量**。走查时至少覆盖：

- 语言：中文（1em/字）与英文各一遍；原版有几种语言就都切一遍。
- 值域：金币/得分/血量/倒计时的**最长形态**（4~5 位数、`x3`、`已暂停` 这类既短又长的按钮文案）。
- 状态：禁用态、冷却态（"技能 8" → "技能"）、选中态（按钮文案被替换）。
- 界面：标题 / 选关 / HUD / 选择面板 / 暂停 / 结算 / 商店——**HUD 与选择面板最容易挤**（定宽 + 数字最长）。

### F6 Button 不是容器：子控件不布局，整轮修复被废掉

- **症状**：想给按钮做两行文案（主文案 + 副行）或"图标 + 文字"，于是 `b = UI.Button{...}` 再
  `b:AddChild(labelA)`、`b:AddChild(labelB)`——真帧上两个 label **叠画在同一点**；回退之后
  刷新代码还在往按钮里写 `\n` 文本、注释还写着旧方案，界面看起来"修了等于没修"。
- **根因**：这个引擎版本下 Button 的子控件不参与布局（库注释只承诺 `minWidth`、无 `text`、
  构造时传 `children` 的用法，`Widgets/Button.lua:186`）。而组合控件的正确做法一直存在：
  **任意控件都支持 `props.onClick`**（`Core/Widget.lua:4100`），所以 `Panel { onClick = …, children = … }`
  就是可点击的容器，子控件正常走 Yoga 布局。
- **修法**：组合控件（药丸、两行波次按钮、图标按钮、建造项）用 **Panel + onClick**；
  真想用 Button+children 就先按铁律 7 用 5 行探针在真帧上验证。
  `t3m lint` 规则：`button-addchild`（高风险）。**改结构用替换，不要用回退**（见 ui-parity.md 第 2.6 节）。

### F7 开发自测开关开着交付：用户看到的是自驱画面，不是你的改动

- **症状**：改完 UI 交付，用户说"几乎看不到变化"——预览里游戏自己跑完了第 1 关、停在结算后的 HUD 上，
  标题屏和正常流程根本没出现。
- **根因**：`M.DEV_SMOKE = true` 被一起提交了。它的启动路径跳过标题屏、自驱打完关卡
  （实测 ~1.5 秒跑完一局），预览永远停在自驱结果上；且这一开关是在"回退"提交里顺手带上的，
  没人再看它一眼。
- **修法**：交付前把 `DEV_* / SMOKE / SELFTEST` 开关全部关掉，harness 本体挪到 `verify/`；
  `t3m lint` 的 `dev-switch-on`（高风险）会在 scripts/ 里拦到模块级开关；
  `t3m mark accept` 还会对"截图比代码旧"与"交付工程里有开发开关"给出警告——
  **每一轮都收尾**：lint → rlog → 重新截图 → `t3m note screenshot`
  （实测一轮修复的三张截图全属于中间提交，最终版一张都没有，等于没人看过交付的那一版）。
  见 ui-parity.md 第 2.6 节。

### F8 对齐表 0/49 行空着就开工：清单生成了 ≠ 清单被用了

- **症状**：`t3m ui` 的清单和 `ui_inventory` 证据都在，修复轮却只改了几个按钮尺寸——
  药丸读数、英雄卡、锚定建造菜单、目标模式、键盘层、速度持久化全都没做，因为第七节
  「逐条对齐表」49 行的「Maker 实现」一列全空着，没人被它逼着逐条过。
- **根因**：门禁只查了清单文件**存在**（生成即存在），没有查它**被用过**。"生成产物"和
  "按产物逐条对照"之间没有强制力，agent 就会挑最容易的部分做。
- **修法**：`t3m mark ui` 现在会拒绝对齐表没填满（49/49 空就拦下），并对"原版控件在转写代码里
  没有对应实现"做下限检查（`t3m ui source/game/ --check dest`，缺失 → 退出码 1）。
  流程上：**填表本身就是设计**——每一行迫使你回答"这个控件做成什么、什么时候显示"。

### F9 界面文案缺 key：按钮上直接显示 `paints` 这种原始 key

- **症状**：标题屏上一个按钮写着小写英文 `paints`（词表里的 key 本身），另一个屏的统计行写着 `kills`；
  玩家看到的不是文案而是变量名。
- **根因**：`t(key)`/`I18n.t(key)` 查不到时**原样返回 key**（两份参考实现都是这个回落），
  所以"词表漏了一条"不会报错，只会把 key 画到界面上。转写时新增的界面（工坊/涂装/结算统计）
  最容易漏——原版有这条词条，转写把控件做出来了却没把词条搬过来。
- **修法**：`t3m lint` 规则 `i18n-missing-key`（高风险）会把"用了但词表里没有"的 key 逐条列出来
  （只按字面量查，动态拼接的 key 不查）；对照原版词典补齐。**界面文案一律走词表**，
  硬编码字面量（例如标题写成 `label("Tower Guard", …)`）会让多语言切换失效——
  `hardcoded-ui-text`（中风险）会点出来。

### F10 首页/菜单屏"差很多"：漏的是没有 data-\* 锚点的骨架件

- **症状**：标题屏的主按钮、菜单列都在，但整屏观感与原版差得远——左上角的星币/宝石 chip 没有、
  右上角齿轮没有、页脚版权行没有，主按钮与菜单列各是各的宽度，图标也没了。
- **根因**：控件清单只列了 `data-a`/`data-r` 这类**有锚点**的控件，而首页的一半是**无锚点的静态件与容器**：
  `.wallet`（读写数值的 chip，绝对定位在左上）、`.corner`（右上角按钮）、`.credit`（页脚）、
  `.logo`/`.tmenu`/`.trow`（菜单列与行）。它们同样有 CSS 盒子模型，也同样是规格，但清单里没列，
  门禁也查不到 → 整块被漏掉。菜单列的**布局关系**同样在 CSS 里：`.tmenu { width: min(340px,100%) }`、
  `.trow .btn { flex: 1 }`（等宽铺满）、`.trow .btn { flex-direction: column }`（图标在上、文字在下）；
  转写时按 140px 固定宽排一行，宽度就差了近一倍。
- **修法**：`t3m ui` 的清单第三节现在会列出**布局骨架**（模板里出现、且带 CSS 的 class + 盒子模型），
  第七节对齐表也把这些骨架件逐行列出——`t3m mark ui` 会要求它们和对齐表一起填满。
  转写时按 CSS 原值：绝对定位的钉在同一个角，等宽的行用 `flexGrow = 1`（不要定宽），
  图标在上文字在下要用 Panel + 两个 Label（见 F1/F6——Button 只有一行）。

## G. 过程反思：这些坑为什么没被提前拦住

- **静态检查的边界**：`maker-lua-lsp --mode check`（0 error）、`t3m lint`（0 高危）、远端构建成功
  ——三者都**不执行**代码，运行时的 nil 调用、渲染路径错误、API 语义错误一律看不见。
- **自检要选对断言层**：几何自检只验数据（顶点/绕序/包围盒）时，上传方式错了也全绿。
  凡"数据 → 引擎"的转换，断言必须落在**引擎侧可观测的东西**上（`GetNumGeometries`、`inView`、像素）。
- **一次只改一类**：把几何、光照、UI 混在一起改，会把多个根因叠加成"看起来像玄学"的现象。
- **先跑通最小闭环再堆内容**：拿到第一帧画面（哪怕只有一个方块）之后再铺棋盘/角色/装饰，
  比"全写完再跑"便宜一个数量级。
- **实跑优先于自证**：本轮的唯一决定性动作是"把本机 runtime 跑起来 + 读 runtime.log + 截图"。
