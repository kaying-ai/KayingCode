# 界面与流程对等（UI parity）

原版的 UI 是一份**规格**：固定的一批控件、固定的尺寸与位置、固定的文案、固定的功能、固定的显隐条件。
"用引擎控件重做一遍，看着差不多"不是转写——它会把控件集合、位置、功能和节奏一起改掉，而且**不会报任何错**：
画面正常、日志干净、`t3m lint` 全绿、远端构建成功。

这篇是 UI 这一步的判定标准与做法。开始写控件代码之前先跑 `t3m ui` 出清单，收尾时按清单逐条核对。

---

## 0. 先出清单，再写控件

```bash
t3m ui source/game/ --out source/UI_INVENTORY.md
t3m note project-info.json ui_inventory source/UI_INVENTORY.md
```

清单里有六样东西，缺一不可：

1. **页面容器**（`#hud` / `#ui` / `#pops` 这类分层）——决定控件的父子与层级（弹窗必须在 HUD 之上）。
2. **CSS 盒子模型**——每个选择器的 `position/left/top/width/height/padding/gap/font-size/border-radius`。
3. **控件清单**——`data-a`（可操作）/`data-r`（读数）/`data-k`（列表项）锚点 + class + 文案 key。
4. **屏幕与导航**——有哪几个屏、谁触发谁。
5. **输入映射**——键盘/指针的每一条绑定。
6. **节奏与计时节点**——`setTimeout`、速度、暂停原因、波次间隔、提前召唤奖励。

`t3m mark project-info.json ui` 会拒绝在没有 `ui_inventory` 证据时标成 done（和 `accept` 一样是有意设计）。

清单是**骨架**：模板字符串里看不见的东西（动态创建的控件、canvas 自绘、逐状态样式、动画）要回源码人工补齐，
补完把第七节「逐条对齐表」的最后一列填满。**填不满就开始写代码，等于又凭印象设计一遍。**

---

## 1. 七条铁律

1. **控件 1:1**：原版有几个控件就转几个。不合并（把"速度+暂停"塞进一个动作栏）、不拆分、不新增——
   尤其**不要新增原版没有的常驻控件**（常驻建造栏、常驻选择面板）。
2. **位置与尺寸直译**：CSS 的 px 值直接进控件 props。常驻控件用绝对定位钉在同一个角，
   同一套 flex/网格关系照搬（Yoga 与 CSS flex 基本同构）。
3. **功能不变**：每个控件的点击动作必须对应原版同一个动作。"下一波"按钮不能变成"开始游戏"按钮，
   也不能把"升级/出售"从塔上挪到固定面板就改叫别的。
4. **显隐条件一起转**：`hidden / on / pulse / poor / lock / sel / ready / down / maxed` 这些状态类决定
   控件何时出现、何时禁用、文案何时替换——只转静态样式等于丢了一半交互。
5. **弹窗锚定，不改常驻**：原版在点到的格子/塔旁边弹菜单的，不要改成常驻工具条或固定面板；
   锚点规则（居中于目标上方、超出屏幕翻转、窄屏改 bottom sheet）一起转。
6. **流程与触发一致**：屏幕集合、每个换屏的触发方式、键盘层，以及**谁来开始第一波**必须与原版一致。
7. **节奏节点一致**：见第 3 节，它们是"游戏运行节奏"的直接来源。

## 2. DOM/CSS → urhox-libs/UI 的直译表

| 原版                                                           | Maker（urhox-libs/UI）                                                                 | 注意                                                                                      |
| -------------------------------------------------------------- | -------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `position:absolute; left/top/right/bottom`                     | 控件 props `position="absolute"` + 同名 `left/top/right/bottom`，**px 原样**           | 安全区变量（`--sat/--sab`）在窗口里取 0，按 0 转                                          |
| `width/height/min-width`                                       | `width/height/minWidth`                                                                | 交互控件**不要**让宽度自适应；正文字号用 `UI.MeasureTextWidth` 量（见 pitfalls F1）       |
| `padding: 0 14px 0 8px`                                        | `paddingLeft/paddingRight/...`                                                         | 四值与简写都支持                                                                          |
| `display:flex; gap/align-items/justify-content/flex-direction` | 同名 props                                                                             | 直接对应                                                                                  |
| `display:grid; grid-template-columns: repeat(4, 72px)`         | 一行 `Panel {flexDirection="row", gap=6}` + 固定宽子项                                 | 栅格列数按数据算时记得算同一份                                                            |
| `border-radius: 20px`                                          | `borderRadius = 20`                                                                    |                                                                                           |
| `border-radius: 50%` + 等宽高                                  | `borderRadius = w/2`                                                                   | 圆形按钮（英雄头像、技能）                                                                |
| 图标（`icon("coin")`，SVG 内联）                               | 图片控件或文字符号                                                                     | 别丢掉图标改成纯文字；原版靠图标区分按钮（速度/暂停）                                     |
| 渐变色 + 内阴影（`.btn` 的 `inset 0 -3px 0`）                  | 主题色 + `borderWidth` 或分层 `Panel`                                                  | 观感项，允许近似，但**位置/尺寸不许动**                                                   |
| `.cd` 的 `conic-gradient` 冷却环                               | 用进度条/遮罩近似，或按角度画                                                          | 冷却**信息**必须保留（玩家靠它判断技能可用）                                              |
| `.hero-hp` 血量条                                              | 内层 Panel 宽度按百分比                                                                | 血量是读数，属于 `data-r` 一类，要接上                                                    |
| 状态类 `.on/.sel/.down/.poor/.lock/.maxed/.hidden/.pulse`      | `SetDisabled` / `SetVisible` / `variant` / 文字或颜色替换                              | 逐个转，别只转一个                                                                        |
| 弹窗（`.bmenu` 锚定在目标上方）                                | 屏内绝对定位 Panel，坐标由 `stage:toScreen(wx, wz)` 得到，再按弹窗尺寸做居中和边界翻转 | 原版规则：居中于目标、`y` 不够翻到目标下方、贴边收进屏幕；窄屏（≤560px）改底部/顶部 sheet |
| 每帧刷新要缓存的读数（原版 `set()` 比较后写）                  | 自己记上次值再写；写值那一步必须是 `widget:SetText(...)`                               | 同名的 local 包装会变成自递归（pitfalls F4）                                              |
| `#pops` 浮字层                                                 | 独立顶层 Panel，绝对定位的池化 Label                                                   | 层级要在弹窗之上/之下按原版                                                               |

## 2.5 组合控件怎么做：Panel + onClick，不是往 Button 里塞子控件

原版控件几乎都是**组合体**：药丸 = 图标 + 数字、波次按钮 = 两行文字 + 进度环、建造项 = 图标 + 名称 + 价格。
Button 只有单行文字，装不下这些。可行与不可行的路（都在本引擎实测过）：

| 做法                                                        | 结论                                                                                                                                                                                               |
| ----------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `UI.Panel { onClick = function() … end, children = { … } }` | **推荐**。`Widget:OnClick` 对任意控件生效（`Core/Widget.lua:4100` 派发 `props.onClick`），Panel 的子控件正常走 Yoga 布局。按下态/悬停态要自己做（换 variant 或改背景色），但位置/尺寸/层级完全可控 |
| `UI.Button { … }` + `b:AddChild(label)`（定宽 + 有 text）   | **不要**。实测子控件不参与布局，全部叠画在同一点（有真帧截图为证）；整轮修复就是这样被废掉的                                                                                                       |
| `UI.Button` + `minWidth`、无 text、构造时传 `children`      | 库注释声称支持（`Widgets/Button.lua:186`），**但必须先用 5 行探针在真帧上验证**（铁律 7）再用                                                                                                      |

`t3m lint` 的 `button-addchild` 会拦第一种错误写法。进度环（`.wb-ring` 的 conic-gradient）没有直接等价物，
用窄进度条或按角度画的多边形近似，**冷却/进度这个信息必须保留**。

## 2.6 修复轮的规矩（改一轮，收一轮）

修复不是"再改一遍代码"，每轮都要收尾，否则上一轮的门禁全部失忆：

1. **每轮结束重跑三件套**：`t3m lint dest`（高风险 0）→ `t3m rlog dest`（PASS）→ **重新做双侧截图与
   `t3m compare`**，更新五个 `compare_*` artifact（非 KayingCode 环境至少更新 `screenshot`）。改完不重跑，
   等于没改——`t3m mark accept` 会对截图或 metrics 比代码/publication 旧给出警告。
2. **改结构用替换，不要用回退**：实测某个做法不行（例如 Button+children 叠画），
   换成可行做法（Panel + onClick）把结构补完，而不是把整块撤回到旧行为——
   撤回之后注释、刷新代码、量宽都会和新结构对不上，出现"看着没变化"的交付。
3. **开发自测开关必须关**：`M.DEV_SMOKE = true` 这类开关会接管启动（自驱跑关、直接跳屏、
   停在结算画面），用户打开预览看到的就是它，而不是你的新 UI。
   `t3m lint` 的 `dev-switch-on`（高风险）专门拦这个；自测 harness 挪到 `verify/`。
4. **对齐表先填再写码**：`source/UI_INVENTORY.md` 第七节每一行都填上「Maker 实现」与「显隐条件」
   再动控件代码。`t3m mark ui` 会在表没填时拒绝（实测一轮 49/49 行空着就开工，结果只改了按钮尺寸）。

## 2.7 首页/菜单屏：先抄骨架，再谈观感

菜单屏最容易"差很多"，因为它的**一半是没有 `data-*` 锚点的容器**。清单第三节的「布局骨架」
已经把这类 class 连盒子模型列出来了，逐条照着转：

| 骨架件（以参考项目为例）                               | CSS 事实                                                                      | 转写要求                                                                 |
| ------------------------------------------------------ | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 顶栏钱包 `.wallet`（星/宝石 chip）                     | `position:absolute; top:12px; inset-inline-start:12px; display:flex; gap:8px` | 绝对定位钉在左上；chip 要有图标 + 数字，数字来自存档（读数）             |
| 右上角按钮 `.corner` / `.hbtn`                         | `position:absolute; top:12px; inset-inline-end:12px`；`44×44; radius 14`      | 齿轮/暂停这类图标按钮**平移位置要一致**，不要挪到底部动作栏              |
| 菜单列 `.tmenu`                                        | `width:min(340px,100%); flex-direction:column; gap:10px`                      | 主按钮与下面几行**同一个宽度容器**，不要各写各的定宽                     |
| 菜单行 `.trow` / `.grid3`                              | `display:flex; gap:10px`，子项 `flex:1`（等宽铺满）                           | 用 `flexGrow = 1`，**不要**给固定 px 宽——实测按 140px 排，宽度差了近一倍 |
| 行内按钮 `.btn`（带图标）                              | `flex-direction:column; gap:3px; font-size:15px`，图标 24~30px 在上           | 图标在上、文字在下 → Panel + 两个 Label（Button 只有一行，见 2.5）       |
| 页脚 `.credit`                                         | `font-size:12px; letter-spacing:.12em; color:rgba(255,255,255,.9)`            | 别漏；这是"这屏做完了"的观感锚点                                         |
| 标题 `.logo h1`                                        | `font-size:clamp(44px,9vw,84px); color:#fff; 多层 text-shadow`                | 字号按 clamp 取、白字 + 描边阴影；两段色（末词高亮）用两个 Label 拼      |
| 遮罩/暗角（`#title` 的上下渐变、`.logo::before` 光晕） | 半透明渐变叠在 3D 画面上                                                      | 用透明 Panel 近似；不做的话标题在亮底上会看不清                          |

**文案一律走词表**：`t(key)` 查不到会**原样返回 key**，界面上就会出现 `paints` 这种字样
（`t3m lint` 的 `i18n-missing-key` 会逐条列出来）。

**平台能力控件可以不做，但要写明**：`gift`（看广告领金币）、结算卡的 `double`/`revive`（广告翻倍/复活）
依赖原平台的广告 SDK，Maker 上没有对应能力——`t3m ui --check` 会一直把它们列为缺失，
处理方式是在交付说明/notes 里写明「平台能力，不做」，而不是硬造一个假按钮。

## 3. 节奏节点（"游戏怎么跑起来"的那几个开关）

这些不是观感项，改掉会直接改掉游戏节奏，必须逐条对齐：

| 节点               | 原版行为（以 Tower Guard 为例）                                                                      | 转写要求                                           |
| ------------------ | ---------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| **第一波由谁开始** | 玩家按"开始"（`.wavebtn` 首次显示 `startWave`）或 Space；**没有倒计时自动开始**                      | 保持手动；不要好心加自动开波                       |
| **波次按钮的显隐** | `canCallWave()` 为假时整颗按钮 `hidden`（透明+不可点），不是变灰                                     | 用 `SetVisible`，且文案/奖励/进度环一起转          |
| **提前召唤奖励**   | 波与波间隙按下 → `gold += ceil(nextT) * 3`，副行显示 `+N`，并有进度环                                | 数值与提示都要转                                   |
| **下一批敌人预告** | 副行画下一波敌人头像（最多 4 个）                                                                    | 这是玩家的决策信息                                 |
| **波次/关卡横幅**  | 开波/进关时 `banner()` 大字提示（含 boss 变体）                                                      | 要转；否则不知道波次开始                           |
| **速度档位**       | `G.speed = G.speed > 1 ? 1 : 2`（**只有 1/2**），并且写入设置持久化、进关恢复                        | 档位数、切换规则、持久化三者一起转；不要自创 3 档  |
| **暂停**           | `pauseReasons` 集合；暂停菜单 4 项：继续/重开/设置/退出；从暂停重开要先清暂停原因                    | 菜单项集合与清理逻辑一起转                         |
| **教程提示时序**   | 第 1 关 `tip(tut1)` @600ms、`tip(tut2)` @6400ms；第 3 关 `tip(tut3)` @800ms；首次开波记 `P.tutorial` | 时序与触发条件照搬                                 |
| **飞怪警告**       | 首次出现飞行敌人时提示一次                                                                           | 一次性提示要保留                                   |
| **结算可达性**     | 过关/失败都进结算卡（星级、奖励、翻倍/复活/下一关/重玩/回地图）                                      | 必须能从正常玩法走到；只在自测里能到的界面等于没有 |
| **进关时的初始化** | 清暂停原因、恢复速度设置、播 banner、清菜单                                                          | 逐条写进进关流程                                   |

## 4. 验收怎么走

1. **对照表**：`source/UI_INVENTORY.md` 第七节每一行都填了"Maker 实现"，且实现里的控件 id 在代码里找得到。
2. **逐屏截图**：每个屏至少一张截图（标题/地图/关卡简报/HUD/建造弹窗/塔弹窗/暂停/结算），
   与原版同屏并排看位置。**注意裁剪与缩放对齐**，别拿缩放后的图比。
3. **触发走查**：清单第五节每一条输入都按一遍（Space 开波、F 速度、Q 技能、H 选英雄、1-8 建造、
   U/A/B 升级、X 出售、方向键+Enter 格子光标、Esc 暂停/关菜单）；第六节每条计时都观察一次。
4. **状态走查**：每个控件在"能点/不能点/已选中/冷却中/已满级/买不起"下的样子都对一遍。
5. **节奏走查**：随便打两波，确认"手动开第一波 → 间隔计时 → 提前召唤奖励 → 自动开下一波"的节奏与原版一致。

> 这一节是 `t3m lint` **查不到**的部分：控件位置、功能、显隐条件都是渲染期行为，静态检查看不见。
> 只有清单逐条对照 + 截图 + 自驱走查能证明它对了。

## 5. 反面案例（Tower Guard 实测，别再犯）

原版 HUD 与转写版对照（取自 `source/game/src/ui/hud.js` + `style-ui.css` 与转写工程）：

| 原版                                                                                                                            | 转写版做了什么                                                                                            | 后果                                        |
| ------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| 顶部**药丸**：金币/生命/波次（图标 + 18px 粗体，38px 高、圆角 20）                                                              | 顶部一行纯文字 label（等级名/波次/得分/生命/金币），且因为刷新函数被同名 local 包成自递归而**一直是空的** | 关键读数消失，玩家无法判断局势              |
| 右上 44×44 图标按钮：速度、暂停                                                                                                 | 挪到右下动作栏里的文字按钮"x1""暂停"                                                                      | 位置与形态都变，肌肉记忆失效                |
| 左下 62×62 英雄头像（带血条、选中/阵亡态）+ 52×52 技能圆钮（冷却环、可用的发光态）                                              | 只有一个文字按钮"技能"，没有头像、没有血条、没有冷却环                                                    | 英雄系统在 UI 上等于不存在                  |
| 右下 150×60 绿色"开始/下一波"按钮：两行（主文案 + 提前召唤奖励/下一波敌人）、右上进度环、`canCallWave` 为假时整颗隐藏、首波脉冲 | 右下 168px 的"召唤下一波"按钮，只有一行文案，禁用而不隐藏                                                 | 开波节奏与奖励信息丢失                      |
| 点空格子 → **在该格子上方弹建造菜单**（72×78 的选项格、描述区、未解锁的下一座塔做预告、买不起/未解锁态）                        | 底部常驻建造栏（96×52 按钮）+ 点格子放置                                                                  | **交互机制被改写**：拾取-放置取代了原地菜单 |
| 点塔 → **在塔上方弹塔菜单**（图标+星级圆点+描述+属性网格+升级/分支卡+目标模式分段控件+出售/满级态）                             | 固定右上选择面板（标题+升级+出售+属性表）                                                                 | 目标模式（优先/最强/最近）整个功能丢失      |
| 键盘：Space 开波、F 速度、Q 技能、H 英雄、1-8 建造、U/A/B 升级、X 出售、方向键+Enter 格子光标                                   | 只有 Space/Q/Esc/Tab/数字键，且数字键语义被改成"预选塔"                                                   | 桌面操作层缺失、语义冲突                    |
| 速度 1/2 档 + 持久化、教程 tip 时序、波次横幅、飞怪警告、暂停菜单 4 项、结算卡可达                                              | 速度 1/2/3 且不持久化；教程/横幅/警告没有；暂停菜单换成"继续/重试/速度/退出"；结算屏正常玩法走不到        | 节奏与引导都变了                            |

这些差异**没有任何一条**会被 `t3m lint`、`t3m rlog` 或远端构建发现。
`t3m ui` 清单 + `t3m mark ui` 门禁 + 本文的第 4 节走查，就是为它们准备的。

## 6. 什么时候可以"不等价"

只在这两种情况：

- 引擎**确实没有**对应能力（例：NanoVG 画不出 conic-gradient 冷却环）→ 用近似实现，
  并在交付说明里写成"做了但不完全等价"，写清差在哪。
- 原版依赖平台能力（广告、SDK 登录、分享）→ 记录为"不做"。

除此之外的差异都是 bug，不是"风格选择"。**已知差异要写具体**：哪一屏、哪个控件、差多少。
