# App 备案签名信息提取工具

## 行为

- 仓库根目录 `scripts/beian/` 提供 Android、iOS、HarmonyOS 三个独立命令行工具，读取已签名发行产物或发行证书，提取备案需要的包名/Bundle ID、公钥和证书指纹。
- 工具只读取输入文件；临时解包和证书文件放入系统临时目录并在结束后清理。工具不得读取、输出、复制或上传私钥、keystore 密码、Profile 密码或用户数据。
- Android 工具接收签名 APK，先验证签名，再从实际 APK signer certificate 提取公钥和 MD5 证书指纹。RSA 公钥提供模数的十六进制和十进制表示；非 RSA 公钥提供证书中的公钥点十六进制。
- iOS 工具接收 IPA 或 `.app`，验证代码签名，从实际签名叶证书提取 Bundle ID、公钥和 SHA-1 证书指纹。RSA 公钥提供模数的十六进制和十进制表示。
- HarmonyOS 工具接收 AppGallery Connect 下载的签名证书链 `.cer`，仅选择其中唯一的非 CA 叶证书，提取公钥、证书 MD5 与 SHA-1 指纹。椭圆曲线公钥以证书公钥点十六进制表示。
- 每个工具支持人类可读文本和 JSON 输出；无法验证签名、缺少唯一签名证书、无法解析公钥或缺少所需系统工具时返回非零状态，并说明如何修复。
- HarmonyOS 备案平台可能把证书 SHA-1 指纹作为签名 MD5 值使用；工具同时输出实际 MD5 与 SHA-1，不替操作者决定平台字段规则。

## 所有者与边界

- `scripts/beian/` 是仓库级发布/备案辅助工具的唯一实现位置；Flutter 移动应用的 `spec/` 是其平台签名输入、字段格式和验收规则的文档所有者。
- 每个平台脚本负责输入文件定位、该平台签名验证和字段语义；共享模块只负责证书链解析、公开密钥格式化、指纹计算、临时目录和输出格式。
- Android 签名验证由 Android SDK `apksigner` 负责；iOS 签名验证和身份读取由 macOS `codesign` 负责；HarmonyOS 证书由 OpenSSL 解析，并应使用发布证书链而不是 CA 根证书或调试证书。
- 任何工具都不构建或重新签名应用，也不连接备案网站或提交表单。签名证书变化时，必须从将要分发的实际产物/证书重新提取。

## 事件与数据流

```text
发行产物/证书 → 平台适配脚本 → 签名/证书校验 → 公开证书字段解析 → 文本或 JSON 输出
私钥与密码 ──────────────────────────────── 不读取、不输出
```

## 验收场景

1. Release APK 签名有效时，输出包名、公钥表示和与 signer certificate 一致的 MD5；签名无效或 `apksigner` 不可用时失败。
2. App Store Distribution 签名的 IPA 或 `.app` 有效时，输出 Bundle ID、公钥表示和 SHA-1；开发签名也可提取，但输出签名身份供操作者区分分发用途。
3. HarmonyOS `.cer` 含 Huawei 证书链时，只使用唯一的非 CA 叶证书计算公钥、MD5 和 SHA-1；只有根/中间 CA 或存在多个叶证书时失败。
4. 三个平台均支持 `--json`，公钥、指纹和包标识字段名稳定；失败时不输出部分成功结果，返回非零状态。
5. 对证书链选择、APK 签名块证书提取和 RSA/EC 公钥编码有自动化测试。
